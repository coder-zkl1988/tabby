## 状态与兼容性

- 保持原有存储结构和错误类型导出路径；公共错误与日期函数移入 `xhs-ops-common.ts`，避免 store 和执行服务互相依赖。
- 旧数据中的重复设备绑定不会静默改写，执行时返回 409。需先取消未完成任务，再调整绑定。
- 取消会立即停止后续派发。现有手机 RPC 到终态才返回任务 ID，无法可靠证明 `currentTaskId` 的归属，因此不再用 `cancelTask("current")`。当前手机任务块继续等待回执，run 保持 running 并显示取消请求，收尾后转为 cancelled。
- 启动恢复先收口遗留 running，再处理队列。前序成功且仍在当日的浏览任务恢复；前序中断、失败、取消、缺失或过期则终止后续。评论任务从未派发则释放草稿，已尝试则保留待核验结果。
- 500 条历史上限不会再淘汰当日或未完成记录；没有可安全清理的旧记录时，新建返回 409。项目包含当日记录或未完成任务时暂不能删除，避免清除当日额度和安全暂停证据。允许删除时同时清理评论草稿。
- 独立复核补充覆盖了取消后崩溃、历史裁剪和删除项目清除证据、误取消同机外部任务等路径。

## 2026-09-08：跨项目设备占用与转移

新项目的账号配置只检查当前卡片内的设备选择，漏掉其他项目已有的绑定，导致选择时看起来可用，保存时才收到 409。现改为加载全局绑定，在设备选项和账号行中展示所属项目、账号，并提供「转移设备并保存此账号」。转移前明确展示来源与目标；普通保存不会自动解除其他账号的绑定。

转移接口先核实手机在线、心跳在 90 秒内、状态空闲且没有当前任务，再在同一次存储 mutation 中解除源绑定并创建或更新目标账号，保留源账号、双方资料和历史。绑定变化、重复绑定、项目缺失、目标已有其他设备、未完成运行和资料应用期间均拒绝转移。资料应用持有可幂等释放的设备占用记录，更新结果不需要重复获取锁。转移返回的账号 ID 立即回填到卡片，后续保存按更新处理；转移本身不触发手机任务。

前端还覆盖账号列表加载失败、全局绑定加载失败、项目切换和刷新绑定信息。加载失败有重试入口；刷新绑定不重置账号草稿。

## 2026-09-09：补回素材步骤与手机终态确认

缺失步骤的原因是账号保存后直接进入浏览计划，工具指引把素材卡当成可选项，执行服务也没有资料前置检查。现在两个账号在原计划卡内先显示完整资料步骤：昵称、简介（星座/MBTI、自我介绍、兴趣介绍）、头像（人物半身照与自然背景）、背景图（地区风景与人物背身），支持一键生成和分别重生成。选择图片并人工校验确认后才显示养号计划，保存草稿不会解锁或自动修改手机公开资料。

后端对创建、开始和定时调度统一检查完整资料及服务端确认记录。编辑或重新生成会清除旧确认；公开 API 不接受伪造确认/应用元数据。应用到手机后的内部结果用草稿快照比较，手机执行期间发生的新编辑不会被旧结果覆盖。

桌面和手机不同步包含两个独立问题：会话助手曾在手机仍执行时收到模型 HTTP 522；取消 RPC 原来在发送命令后立即报告成功，未等手机停止。修复后聊天通知不作为手机任务终态，取消必须收到手机 aborted 回执，未确认则保留占用及恢复隔离。浏览 CALL_USER 也走定向取消，不再继续派发下一任务块；受限/限流原因优先于通用人工处理提示。

登录检查的 missing receipt 已在真机复现：旧 APK 返回成功及自然语言，但缺少 PREPARATION_JSON。Android 现有 GELab 全局禁止 JSON 的动作外壳说明与结果 JSON 要求发生歧义，现明确区分，并在 COMPLETE 接受前强校验四字段合同，最多两次格式纠正。控制器仅在成功却缺少有效回执时增加一次只读复核，不能重复安装、登录或取验证码。
