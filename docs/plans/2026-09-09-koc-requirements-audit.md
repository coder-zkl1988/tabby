## 结论与修复优先级

目前实现的是“项目/画像/人设编辑 + 四项素材生成确认 + 手机登录准备 + 浏览任务与复盘”，尚不是脑图要求的完整“建号后养号”流程。此前把字段存在、技能说明存在、单元测试通过当成了流程覆盖充分，遗漏了前后阶段的依赖关系及业务完成证据。

| 编号 | 优先级 | 实际缺口 | 用户可见后果 |
|---|---|---|---|
| G01 | P0 | 素材确认直接解锁养号，不要求手机资料应用和验收成功 | 从未配置手机账号，甚至应用失败，仍能开始养号 |
| G02 | P0 | 性别、生日/年龄、地区、平台兴趣标签未接入资料应用；没有独立建号完成状态 | 脑图“按流程创建账号”仅执行昵称、简介、头像、背景四项 |
| G03 | P0 | 目标账号身份与资料生效缺可靠核验 | 看见任一已登录主页即允许继续，不能证明是计划绑定的目标账号 |
| G04 | P0 | 资料及浏览存在无充分证据的“完成”判定 | 资料任务失败但四项自报 done 可被记 applied；浏览无结构化记录仍可 completed |
| G05 | P1 | 画像确认、人设完整性未形成阶段门禁 | 空画像、未确认画像、空人口学信息也能创建运营账号；补四项素材后可绕过前序阶段 |
| G06 | P1 | 没有明确的 N 数量生成/重生成入口和批次验收；分布与标签数量未落实 | 默认 10 个只在提示词中；账号数量、人设完整性和整体分布缺确定性的验收步骤 |
| G07 | P1 | 上游修改没有关联复核；旧卡片可能覆盖新画像 | 业务/画像/人设已变，下游仍显示旧确认，下一轮任务可能继续沿用旧兴趣池 |
| G08 | 增强建议 | 长期档案已保存，可补跨会话项目选择与集中编辑入口 | 原卡可编辑，独立入口能改善找回体验；不列为明确需求遗漏 |
| G09 | P1 | 脑图 80–100 篇未成为默认目标且统计口径未明确；严格 >10 秒、互动比例未按原要求落实 | 目标设为 100 时，单段自动建议可能被截为 52 篇；停留可低于要求，互动比例实际是分块上限 |
| G10 | P1 | 随机浏览、刷新、评论阅读已有技能，但缺执行证据；“读完评论区”被缩为至少 3 条 | 无法从桌面结果确认手机实际遵守这些行为要求 |
| G11 | P2 | 关注目标类型缺配置 | 不能限定关注的账号类型；另建议补充失败字段续跑和人工上传兜底，后两项不是独立的硬性需求 |
| G12 | 验收 | 未完成 D 第五节的 10 人设、2–3 账号完整业务验收 | 现有测试及只读登录检查不能证明“建号→养号→复盘→下一轮”可完整使用 |

P0 为进入养号的前置完整性与结果真实性；P1 为明确需求遗漏或关键流程断点；P2 为配置能力。G08 是增强建议，不计入硬性遗漏。身份匹配、资料生效核验与阶段门禁是根据脑图流程顺序推导的正确性要求，不是文档逐字条款；已有账号可通过资料核验进入养号，不需要每轮重写资料。评论比例等范围差异另列，不擅自把默认关闭评论改成自动评论。

## 不应混为遗漏的范围差异

1. **评论**：脑图要随机 3%，D 第一阶段默认不做。当前独立审核评论是已有能力，不是“完全没有评论”；缺的是脑图那种比例策略，同时存在范围冲突。
2. **80–100 篇**：脑图给出目标，D 没限定篇数，代码/旧计划默认采用较小目标。脑图未明确单次或每日，不能直接断言只允许一次完成；现有两段可达每日 100，但默认计划及单段建议与该目标有差距。
3. **人工上传与 AI**：D 允许首期先上传/素材库，M 要生成。AI 实现本身满足 M，未同时提供手工替代入口不算硬性遗漏，只列为恢复能力建议。
4. **自动内容质量判定、自动兴趣优化、复杂模型训练、自动发布/私信/成交**：D 明确暂不处理，不能为了“完整”加成必做项。
5. **独立档案库页面、档案版本历史、项目级互动继承、自动图像语义审核、仅重试失败资料项**：可作为后续增强，但不是本次两份需求明确要求的独立验收项。
6. **新号注册**：已有验证码登录不应被说成完全没有账号接入；产品缺的是独立建号过程、明确新号完成状态和身份核验，平台是否在首次登录时隐式注册仍需实机验证。
