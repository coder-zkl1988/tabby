# KOC 建号与养号缺口补齐

基于 [逐项审计](./2026-09-09-koc-requirements-audit.md)，本轮授权实现并验证流程断点。保留已有用户数据，不自动提交。

## 完成标准

1. 客户最低输入完整，画像由独立确认接口保存；陈旧卡片不能覆盖新数据。
2. 按指定 N 生成人设，展示目标与实际分布，人工确认差异化；档案垂直标签 1–2 个、泛标签 2–3 个与长期兴趣池区分。允许保存未完成草稿，但不允许绕过确认进入执行。
3. 上游客户/画像变化使关联人设及素材待复核，人设/兴趣变化使素材待复核。并发变更不能被旧任务结果重新确认。
4. 手机建号按安装登录、目标账号核对、八项资料配置、独立只读核验顺序完成。明确生日由运营提供，不从年龄范围猜测。缺字段、未生效、身份不符或验证失败时不启动养号。
5. 普通浏览必须有完整且一致的记录；手机失败、缺回执、矛盾记录均不得标记完成。手机报告的停留/评论阅读与宿主可观测时间交叉检查，并明确其证据边界。
6. 默认每日 90 篇、两段，任务容量不足明确提示。停留至少 11 秒；互动按整轮累计预算计算，保留每日上限；关注目标类型可配置；评论继续默认关闭、独立审核。
7. 运行相关回归、全仓类型检查、lint、测试并记录现存非本次问题；桌面端验证关键交互。真实手机验收以用户确认的目标账号和资料为前提，不把桩或结构化回执当作全部业务验收。

## 实施分工与顺序

- 共享契约、存储依赖失效、确认/生成人设接口及 SDK：主代理。
- 客户、画像、人设编辑/生成/人工复核：前端代理。
- 手机准备、八项配置与独立核验、资料卡和技能同步：手机代理。
- 执行门禁、记录真实性、计划/互动预算与运行卡：运行代理。

先补失败案例，再逐层实现；接口就绪后统一生成 SDK，最后集成测试与桌面验收。人工上传、独立档案页面、仅重试失败项为增强建议，不扩展为本轮必做；脑图评论 3% 与 V0.1 默认禁评的冲突保留 V0.1 范围。
